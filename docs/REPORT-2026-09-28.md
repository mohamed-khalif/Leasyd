## 1. Goal

A serverless, multi-tenant SaaS back end for logs, traces and metrics (OTLP) whose storage is
plain S3 and whose compute is Lambda only — no always-on cluster (no Elasticsearch/ClickHouse
nodes, no Kafka). Cost scales to ~zero with no traffic and stays near raw AWS unit prices under
load. Targets the platform is tested against:

| Target | Value |
|---|---|
| Freshness: record sent -> findable by lookup/query | p99 < 60 s |
| Query: 1 day of the largest tenant (aggregate) | < 5 s |
| ID lookup (trace id / request id) across 30 days | < 3 s |
| Ingest scale proven | 50 GB/h across 100 tenants (Zipf-sized) |
| Correctness | no record lost or counted twice across any crash point; results equal Athena |
| Isolation | a tenant can never read another tenant's data, enforced by IAM, not app code |
| Cost (ingest + fast lane) | cents per GB; compaction ~$0.02/GB; storage S3 Parquet (~7-10x smaller than JSON) |

## 2. Architecture (as deployed)

```
client --OTLP (protobuf/JSON, API key)--> API Gateway (REST, usage plans)
   -> REQUEST authorizer (sha256(key) in obs-tenants; active, or expiring until expires_at)
   -> obs-ingest Lambda: OTLP -> JSON lines, gzip per record (RECORD_COMPRESSION=gzip)
   -> Firehose, one stream per tenant per signal: obs-t-<tenant>-<signal>
        pass-through (CompressionFormat UNCOMPRESSED), buffer 30 s / 64 MB
   -> s3://obs-data-<acct>-us-east-1/_incoming/tenant=T/<signal>/dt=D/hour=H/<file>.json.gz

FAST LANE (per raw file, EventBridge "Object Created" -> obs-recent-indexer, 3008 MB)
   compact.compact(signal, [file], ..., one_bloom=True)   # same parser as compaction
   -> Parquet per (service, event hour): data/tenant=T/<signal>/_fast/dt=/hour=/service=/part-fast-<sha16>-NNN.parquet
   -> ONE bloom for the whole raw file: data/tenant=T/<signal>/_fast/_bloom/fast-<sha16>.bloom (inline if <=1 KB)
   -> raw-file record  pk=T#_raw#sig#D#H, sk=<raw key>: entries + S3 objects (written BEFORE upload/index)
   -> index entries kind=raw in obs-index (pk=T#sig#service, sk=<min_ts>#fast-<sha16>-NNN)

COMPACTION (obs-compaction-dispatcher every 15 min; closed hours + 10 min grace)
   plan per tenant/signal/arrival-hour: chunks of <=2,000 files / <=200 MB gzip (plan item status planned)
   obs-compaction-worker (3008 MB, 900 s, async, 0 retries; the next dispatcher run retries planned plans):
     download -> compact.compact(...) -> data/tenant=T/<signal>/dt=/hour=/service=/part-<batch>-NNN.parquet
     bloom per file (inline or data/.../_bloom/<relpath>.bloom), 12-byte ID digests -> _ids/dt=/hour=/g=/batch.bin
     index kind=parquet, usage record (obs-usage), commit (status committed)
     retire fast-lane entries + their _fast objects, delete raw inputs, delete plan
   Handover rule (lookup._visible): plan planned -> fast-lane copy visible; committed -> Parquet visible.

obs-day-sealer (every 15 min): seals hour filters 20 min after the hour and day filters 2 h after the day,
   sharded (16 groups x <=256 subshards); trusted only if sealed == dirty and one fieldset.

QUERY: obs-query (coordinator) -> lookup (time range -> day/hour filters -> per-file blooms, 64 threads)
   -> plan_chunks (64 MB per worker, <=64 workers) -> obs-query-worker x N
   -> DuckDB read_parquet in place via TenantS3 (fsspec, S3 range reads, tenant-scoped STS credentials)
   -> partial aggregates (histogram percentiles) merged by the coordinator.
Isolation: every read uses obs-tenant-reader assumed with session tag tenant=T (IAM ABAC).
Tenant admin: obs-tenant-admin (create, rotate with grace, revoke, usage, delete with purge passes).
```

Code: `services/compaction/` (compact.py = OTLP JSON -> rows -> Parquet; handler.py = fast lane,
dispatcher, worker, sealer; lookup.py; query.py; bloom.py; dayfilter.py; layout.py), `services/ingest/`,
`services/tenants/`, `services/loadgen/`. Infra: one CloudFormation stack per phase (`infra/*.yaml`,
`infra/deploy-*.sh`). Lambda memory is capped at **3008 MB on this account** (4096 was refused).

## 5. Open issue (for the next session)

**Freshness p99 74 s at 50 GB/h (target 60 s).** Cause: the fast lane runs the same parser as
compaction; the spill-safe `_ATTR_MAP` (7b2f5d7) is ~1.8x slower, so the fast lane's p99 per
file went 13 s -> 21 s. The fast lane only ever parses ONE raw file (Firehose caps a file at
64 MB of gzip records; observed ~15-17 MB / ~160-180k records for the largest tenant), where the
fast CASE form is memory-safe (1M records fit in 1.8 GB). Compaction chunks (up to 2M records)
need the spill-safe form. See `docs/NEXT-SESSION.md`.

Also pending: confirm the s3e hour-13 chunks compact without errors; fault tests + soak; delete
`t6-*` tenants and `obs-phaseT6`; lock down Phase 0 (`AllowTestAssume=false
EnableLifecycleTest=false`); merge to main.

## 6. Lessons recorded

- Measure memory on the largest real input, not a representative one (ac003b8 was checked on 400k records).
- Measure only after the system is in the state being tested: two ID-lookup runs measured stale
  pre-deploy entries and chunks stuck by the OOM, not the new code.
- A fix in shared code (compact.py) changes every caller: the compaction fix slowed the fast lane.
