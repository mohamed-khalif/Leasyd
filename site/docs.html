Leasyd documentation

Last updated 5 October 2026

Leasyd stores and searches your logs, traces and metrics in Leasyd Vault, one store for every signal that the app, the API, PromQL, SQL and AI agents all read. You send data with OpenTelemetry, the open standard most languages and tools already support, so there is no Leasyd agent or SDK to learn and nothing locks you in.

Quickstart

  1. Start a free trial: 7 days, every feature, no card. You'll get an email with a temporary password.
  2. Sign in and open Get started. Pick what you're running: it shows the exact commands, with a new API key filled in.
  3. Start your app with the settings shown. Data appears under Logs, Traces and Metrics within about a minute.

The settings every OpenTelemetry SDK understands:

export OTEL_SERVICE_NAME=my-service
export OTEL_EXPORTER_OTLP_ENDPOINT=https://ingest.leasyd.com
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_EXPORTER_OTLP_HEADERS=x-api-key=YOUR_API_KEY

API keys

Keys are made in Settings › API keys by the account's owners. Each key has one job:

  • Send data (ingest): may only send logs, traces and metrics. Safe to put in your apps' configuration: it can't read anything back.
  • Read data (API): may only query, through the query API and the MCP server.

A key is shown once, when it's made: store it like a password. We keep only a hash of it. Revoke a key in Settings and it stops working within about a minute. A new key can take a minute or two before it's accepted everywhere.

Leasyd takes OTLP over HTTP, not gRPC. For tools that only speak gRPC, run an OpenTelemetry Collector next to them and let it forward over HTTP.

Java

The OpenTelemetry Java agent instruments most frameworks with no code changes:

curl -fsSL -o opentelemetry-javaagent.jar \
  https://github.com/open-telemetry/opentelemetry-java-instrumentation/releases/latest/download/opentelemetry-javaagent.jar
export OTEL_SERVICE_NAME=my-service
export OTEL_EXPORTER_OTLP_ENDPOINT=https://ingest.leasyd.com
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_EXPORTER_OTLP_HEADERS=x-api-key=YOUR_API_KEY
java -javaagent:opentelemetry-javaagent.jar -jar your-app.jar

JVM metrics (heap, garbage collection, threads) appear in Dashboards › Leasyd - JVM.

With gunicorn or uvicorn, put opentelemetry-instrument in front of their command. Runtime metrics: Dashboards › Leasyd - Python.

Ruby

Add the OpenTelemetry gems (opentelemetry-sdk, opentelemetry-exporter-otlp, opentelemetry-instrumentation-all, and for metrics opentelemetry-metrics-sdk ~> 0.19.0 and opentelemetry-exporter-otlp-metrics), configure them at start-up with OpenTelemetry::SDK.configure { |c| c.use_all }, and set the same environment variables as above. Get started › Ruby in the app has a small file that adds runtime metrics (CPU, memory, garbage collection) for Dashboards › Leasyd - Ruby.

Other languages

Go, .NET, PHP, Rust, Erlang/Elixir and others have OpenTelemetry SDKs: see opentelemetry.io/docs/languages. Configure their OTLP/HTTP exporter with the endpoint and header above.

Linux servers

On a server (Amazon Linux 2023 or Ubuntu 22.04+, x86 or ARM), Get started › Linux server installs an OpenTelemetry Collector set up for Leasyd. It sends the server's CPU, memory, disk, network and system logs every 30 seconds (Dashboards › Leasyd - Hosts), and accepts your apps' data on localhost:4318 (HTTP) and localhost:4317 (gRPC), so apps on that server need no key.

AWS Lambda

  • Metrics for every function (invocations, errors, duration, throttles): a CloudFormation template from Get started › AWS Lambda streams them from CloudWatch to https://ingest.leasyd.com/v1/aws/cloudwatch-metrics through Amazon Data Firehose. AWS bills the stream and Firehose in your account.
  • Each invocation and its logs: add the OpenTelemetry Lambda layer for your runtime and set AWS_LAMBDA_EXEC_WRAPPER=/opt/otel-instrument plus the settings above.

Functions appear under AWS Lambda in the app.

Logs, traces and metrics

Logs and Traces search everything you've sent in the last 30 days: filter by service, severity, any attribute or text, and open a trace to see each span with its logs. Metrics charts any metric over time. Service map draws your services and the calls between them, from traces. Query builder and SQL answer any other question. The AI SRE can look through your data with you to explain an incident.

Dashboards and alerts

Leasyd comes with dashboards for the JVM, Node.js, Python, Ruby, hosts and AWS Lambda; any chart can be added to your own dashboards. Alerts watch a query (an error rate, a latency, a check failing) and email you when it crosses a threshold. SLOs track an objective such as 99.9% of requests under 300 ms.

Synthetic checks

Checks call your sites and APIs from AWS us-east-1 every 1, 5, 15, 30, 45 or 60 minutes:

  • HTTP checks: one request or several steps (log in, then call an API with the token), with conditions on status, time, headers and body. Secrets are encrypted and never shown again.
  • Browser checks: a real Chromium browser opens pages, clicks and types, and records page speed and screenshots.

Only check systems you own or are allowed to test. Up to 20 checks per account; maintenance windows pause alerts during planned work.

Drop rules

Drop rules discard data you don't need as it arrives (debug logs, health-check requests, noisy metrics), so you pay only the small ingest price for it and never the storage price. Set them in Account › Drop rules: each rule picks a signal, one to five conditions, and how much of the matching data to keep (0% drops it all; 10% keeps one in ten, whole traces at a time). The first rule a record matches decides. The page shows how much of the last 24 hours each rule would have matched before you save it. Changes apply within a minute.

Query API

Query your data from scripts and other tools with a Read data key:

curl -s https://ingest.leasyd.com/v1/query \
  -H "x-api-key: YOUR_READ_KEY" -H "content-type: application/json" \
  -d '{"promql": "sum by (service_name) (rate(leasyd.spans{span_kind=\"SERVER\"}[5m]))",
       "start": "2026-10-05T00:00:00Z", "end": "2026-10-05T06:00:00Z", "step": 60}'

The body is one of:

  • PromQL: {"promql", "start", "end", "step"} for a range, or {"promql", "time"} for one instant. Answers in the format of Prometheus' HTTP API. Besides your own metrics, PromQL sees leasyd.spans, leasyd.span.duration (a histogram) and leasyd.logs, counted from your traces and logs.
  • SQL: {"sql", "start", "end"}, read-only, over the tables logs, spans and metrics.
  • JSON: {"signal", "start", "end", "where", "group_by", "aggs", "search"}; the app's Query builder shows the JSON of any query you build.

A query still running after 20 seconds (or sent with "async": true) answers 202 {"job"}; ask GET /v1/query/{job} until it answers 200. Limits: 600 queries a minute, and a daily search allowance that grows with how much data a query reads (the app shows today's use in Settings).

AI agents (MCP)

Leasyd has an MCP server, so AI agents and coding assistants can investigate your systems with you: "why did checkout get slow after 2 pm?", "show me the errors behind this trace". They get the same read-only tools as Leasyd's AI SRE: services overview, PromQL, log and span search, a whole trace, top values, SQL, synthetic checks and alerts. They can read, never change anything, and only your account's data.

Team

Invite teammates in Settings › Team; there's no charge per person. Owners manage people, API keys, drop rules and billing; members use everything else.

Billing

After the trial you pay for what you use, billed monthly in US dollars through Stripe; see Pricing. To subscribe, an owner opens Settings › Billing › Add payment details. Nothing is charged upfront: each month's invoice counts the records received, the records stored (kept 30 days) and the check runs. Usage & cost in the app shows this month so far. Manage billing changes the card, downloads invoices or cancels; a cancelled subscription stops accepting new data at the end of the period you've paid for.

Retention and deletion

Data is kept for 30 days plus the current day (UTC), then deleted automatically. Drop rules discard data before it's stored. To close your account and delete all of its data, email support@leasyd.com from an owner's address: everything is deleted within a few days.

Security

  • Data is sent and shown over HTTPS only, and encrypted at rest on AWS (us-east-1).
  • Each account's data is stored separately; every query runs with credentials that can only read that account's data.
  • API keys are stored as hashes; check secrets are encrypted with a dedicated key.
  • Leasyd stores what you send as it is: keep passwords, card numbers and other sensitive personal data out of logs and attributes (the OpenTelemetry Collector can remove or mask them before they leave your systems).
